# Maintainers

Maintainers are the code owners who review and approve changes. They triage
issues and keep the project healthy. For the purposes of
[GOVERNANCE.md](GOVERNANCE.md) and [CONTRIBUTING.md](CONTRIBUTING.md), the
maintainers listed here are the members of the Solace Nisshi team.

[`.github/CODEOWNERS`](.github/CODEOWNERS) grants approval rights. This file
names the same people and says how the list changes. A pull request that adds
or removes a maintainer changes both files. If the two disagree, `CODEOWNERS`
wins, because GitHub enforces it.

## Approving a proposal

A proposed change is approved when a maintainer listed above comments on its
issue to say so.

## Becoming a maintainer

Maintainer status is offered to contributors who have made sustained,
substantive contributions and shown good judgment in reviews and design
discussion.

1. An existing maintainer nominates the contributor by opening a pull
   request that adds them to this file and to `CODEOWNERS`.
2. A maintainer other than the nominator approves the pull request. That is
   the bar branch protection enforces for any change. A maintainer who objects
   requests changes on the pull request, which blocks the merge until they
   approve or the review is dismissed. The pull request's history records a
   dismissal.
3. The nomination merges.

If you think you are ready, ask a maintainer to nominate you.

## Stepping down

A maintainer can step back at any time by opening a pull request that
removes them from this file and from `CODEOWNERS`. A maintainer who has
been inactive for a sustained period may be moved to an emeritus state. The
move is a pull request, approved like a nomination, that takes them out of the
table above and out of `CODEOWNERS`, and lists them under Emeritus
maintainers. Emeritus maintainers are thanked here and no longer review or
approve changes.
